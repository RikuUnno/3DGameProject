ファクトリーメソッド：簡潔設計メモ
目的
- シーン/コード間で共通の生成ルールを持たせる（型登録・プレハブ・パラメータ生成）。
- 生成責務を集中させ、プレハブ・プール・非同期ロードを後から容易に追加できるようにする。

基本方針（シンプル）
1. シングルトン `GameObjectFactory::Instance()` を持つ（または DI で注入可能にする）。
2. key（文字列）→ creator 関数 を登録するレジストリを持つ。
3. `Create(key, params)` は `std::unique_ptr<GameObject>` を返す（所有は呼び出し側／Scene が持つ）。
4. Factory は生成のみを行い、`Awake`/`Start` 等のライフサイクル呼び出しは Scene 側で行う。

最小 API（例）
- `using VariantMap = std::unordered_map<std::string, Variant>;`
- `using Creator = std::function<std::unique_ptr<GameObject>(const VariantMap&)>;`
- `class GameObjectFactory {`
  - `static GameObjectFactory& Instance() noexcept;`
  - `void RegisterCreator(const std::string& key, Creator c);`
  - `std::unique_ptr<GameObject> Create(const std::string& key, const VariantMap& params = {});`
  - `bool IsRegistered(const std::string& key) const;`
  - `};`

登録パターン
- 型登録（テンプレートヘルパ）:
  - `template<typename T> RegisterType("Player")` が `RegisterCreator("Player", [](params){ return std::make_unique<T>(params); })` を行う。
- カスタム登録:
  - `RegisterCreator("Boss", [](params){ auto go = std::make_unique<GameObject>(); /* comp追加 */ return go; });`
- プレハブ登録:
  - JSON をパースして `Creator` を生成し `RegisterCreator("Goblin", prefabCreator)`。

使用例（シーン内）
- `auto go = GameObjectFactory::Instance().Create("Player", { {"hp","100"}, {"pos","0,1,0"} });`
- `scene->AddGameObject(std::move(go));` ← `AddGameObject` 内で `Awake()/Start()` を呼ぶ（設計ルールにする）。

拡張機能（段階的追加）
- オブジェクトプール：`CreateFromPool(key)` / `ReleaseToPool(std::unique_ptr<GameObject>)`。
- 非同期（Deferred）生成：`RequestCreate(key, params, callback)`。リソースロード完了で main スレッドにコールバック。
- コンポーネントファクトリ：コンポーネント名→コンストラクタで Prefab 復元を容易に。

運用上の注意
- Thread-safety：レジストリ操作は `std::mutex` で保護。だが生成（特に DxLib 呼び出し）はメインスレッドで行う。
- 所有のルールを明確に：Factory は `unique_ptr` を返し、Scene/SceneManager が所有して管理する。
- ライフサイクル呼び出しの場所を決める：Create 時に `Awake` だけ呼ぶか、Scene に追加されたタイミングで `Start` を呼ぶかを統一する。
- エラー処理：未登録 key はログ出力／例外投げのどちらかに統一する（プロジェクト方針）。
- Prefab パラメータ差分：Create 時の `params` をプレハブデータへマージできると柔軟。

利点まとめ（短く）
- 生成ロジックが一箇所に集中し保守性向上。
- プレハブ・プール・非同期の導入が容易。
- シーン横断で同一生成ルール・データ駆動化が可能。

実装の次ステップ（推奨）
1. `GameObjectFactory.h/.cpp` を雛形で追加（上の最小 API を実装）。
2. 起動時に代表的な型／プレハブを `RegisterCreator` で登録。
3. Scene の `AddGameObject(std::unique_ptr<GameObject>)` を実装して `Start()` 呼び出しを管理。
4. 必要に応じてプールや Deferred 機能を追加。

短いチェックリスト（導入前確認）
- Factory から返す `GameObject` の初期状態（Awake/Start 呼び出しタイミング）を仕様化する。
- Prefab のフォーマット（JSON の schema）を決める。
- マルチスレッドで生成要求が来た場合の排他と main-thread 実行ルールを定める。
