# 3DGameProject 実装手順（最適化済）

概要
この手順書は「最短で動く」を優先した実装順。各フェーズは「実装（最小） → テスト → 拡張」で進める。

前提・ツール
- OS: Windows 10/11
- IDE: Visual Studio 2022
- ライブラリ: DXライブラリ
- コンパイラ: MSVC（C++20）
- Visual Studio 設定参照: __Project > Properties__, __VC++ Directories__, __Linker > Additional Library Directories__
- ビルド／実行: __Build > Build Solution__, __Debug > Start Debugging__

----------------------------------------
フェーズ 0 — 準備（必須）
1) リポジトリをクローンし、Visual Studio でソリューションを開く
2) DXライブラリの Include/Lib をプロジェクトに設定（__Project > Properties__）
3) `Assert.h` / `Assert.cpp` が Debug ビルドで機能することを確認
テスト: Debug でビルド→起動してウィンドウが開くこと

----------------------------------------
フェーズ 1 — コア基盤（最初に実装）
目的: 最小限の更新／描画ループとオブジェクト管理を動かす
実装（最小）
- Transform 構造体（位置・回転・スケール）
- GameObject（Transform + Update/Render の仮実装）
- Component 基底クラス、AddComponent<T>() ヘルパー
ファイル例:
- Engine/Transform.h
- Engine/GameObject.h/.cpp
- Engine/Component.h/.cpp
テスト:
- Main シーンに数オブジェクトを生成し、Update/Render が呼ばれることを確認

----------------------------------------
フェーズ 2 — シーン管理（次に）
目的: シーン切替とライフサイクル管理を確立
実装（最小）
- Scene 基底（Load, Unload, Update, Render）
- SceneManager（ChangeScene, Push/Pop）
ファイル例:
- Engine/Scene.h/.cpp
- Engine/SceneManager.h/.cpp
テスト:
- シーン切替でオブジェクトが正しくロード／アンロードされることを確認

----------------------------------------
フェーズ 3 — レンダリング基盤 & ライティング
目的: 描画と簡易ライティングを動作させる
実装（最小）
- MeshRenderer コンポーネント（固定メッシュ、最小マテリアル）
- LightingInit() を拡張（Main.cpp を利用）
- デバッグ描画（ワイヤーフレーム、コライダー可視化トグル）
テスト:
- サンプルメッシュをシーンに置き、描画されることを確認

----------------------------------------
フェーズ 4 — 当たり判定（Collision）最小実装
目的: 衝突検出の基本を確立（簡単な判定から）
実装（最小）
- Collider 抽象（virtual Test）
- SphereCollider と AABBCollider
- CollisionManager（初期は N^2 チェック）
- 衝突イベント: OnCollisionEnter/Exit（GameObject 側コールバック）
ファイル例:
- Physics/Collider.h/.cpp
- Physics/CollisionManager.h/.cpp
テスト:
- 複数オブジェクトで当たり判定イベントが正しく発行、デバッグ描画で確認
拡張（後で）
- Broad-phase（Spatial Hash / Quadtree / BVH）
- 詳細な Narrow-phase（OBB / メッシュ）

----------------------------------------
フェーズ 5 — 物理とキャラクター基礎
目的: プレイヤーや NPC の基本的な移動・入力・物理反応
実装（最小）
- CharacterController（入力受け取り、移動、簡易重力）
- StateMachine（列挙型ベース）
- OnCollision で床判定・壁判定を行う
ファイル例:
- Gameplay/Character.h/.cpp
- Gameplay/CharacterController.h/.cpp
テスト:
- キー入力で移動・ジャンプし、床に着地することを確認

----------------------------------------
フェーズ 6 — アニメーション & 表現
目的: 見た目整合（アニメ切替→ブレンド）
実装（最小）
- AnimationController（状態ごとに即時切替）
- 後でブレンド、IK 等を追加
テスト:
- 歩行／待機の切替が入力や StateMachine と連動すること

----------------------------------------
フェーズ 7 — シーンデータ & アセット管理（データ駆動化）
目的: 外部データでシーンとプレハブを定義
実装（最小）
- JSON ベースのシーン定義ロード（`nlohmann::json` 等）
- アセットマネージャ（テクスチャ・メッシュのキャッシュ）
テスト:
- JSON からシーンを構築して起動できること

----------------------------------------
フェーズ 8 — AI / NPC / ゲームロジック
目的: NPC とゲームルールを実装
実装（段階的）
- 簡易 AI（Waypoint、状態遷移）
- ScriptComponent でロジック注入
テスト:
- NPC が想定通りの行動をすること

----------------------------------------
フェーズ 9 — デバッグ・テスト・プロファイリング
- デバッグ描画のトグル化（コライダー、ワイヤー、ログ）
- ユニットテスト（Collider の代表ケース）
- プロファイラでボトルネック計測（必要なら詳細追加）
注: パフォーマンスは CollisionManager とレンダラーを優先確認

----------------------------------------
フェーズ 10 — リリース準備
- __Release__ ビルドで最終チェック（デバッグ描画オフ、Assert 無効）
- 不要ファイル除外、bin/ と assets/ を同梱、README.md 作成

----------------------------------------
テストチェックリスト（実装毎）
- 各フェーズでビルド成功 → 最低 1 回の実走行テスト
- 当たり判定: 境界条件（接触点、微小重なり）で安定
- メモリ: オブジェクト生成／破棄でリークがないか確認（簡易ツール／ログ）

----------------------------------------
優先度（短）
1) コア基盤（GameObject/Component）
2) シーン管理
3) レンダラー & ライティング
4) 当たり判定（Sphere/AABB）
5) キャラクター基礎（入力・物理）
6) アニメーション・アセット管理
7) 最適化・AI・拡張

----------------------------------------
補足
- 各フェーズのヘッダ／ソーススケルトンを自動生成可能。どのフェーズを先にコード化するか指示をください
